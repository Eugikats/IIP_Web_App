## 1. Authority and rules

This matrix converts the governed interaction contracts into atomic requirement, acceptance, permission, audit, flow/state/screen/API, and validation links. It complements the baseline RTM; it does not create a runtime permission, audit action, route, state enum, or provider policy.

- Requirement authority: `iip_release_1_requirements_baseline.md`.
- Measurable gates: `iip_mvp_acceptance_criteria_register.md`.
- Interaction meaning: `iip_release_1_interaction_authority_and_inventory.md` and its companion contracts.
- Current permissions: exact `Permission` enum values plus route/Application/object/state enforcement; missing semantics remain `PERM-GAP-*`.
- Current audit: exact action names from current factories/services; missing coverage remains `AUD-GAP-*`. Audit is not telemetry or notification.
- Screens: `IA-SCR-*`; task regions: `REG-R1-*`; UI states: `ST-R1-{SURFACE}-{CODE}`.
- `Mapped` means the sources link; it is not implementation, accessibility, staging, or UAT completion.

Required audit fields when applicable: tenant/workspace scope, actor/type, case/document/object, action, before/after state, evidence IDs, provider/confidence, approval, reason, correlation, and timestamp. Safe metadata rules in `R1-PRI-004` always apply.

## 4. Completion rule

The interaction RTM is source-complete only when every registered action has one row and every referenced requirement, acceptance criterion, permission, audit action/gap, flow, screen/region/state, and UAT/test ID resolves. Release readiness additionally requires environment-matched implementation, accessibility, provider, audit-correlation, protected UAT, and approval evidence.
