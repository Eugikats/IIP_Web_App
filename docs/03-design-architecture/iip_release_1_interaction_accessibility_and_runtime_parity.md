## 1. Authority and use

This artifact makes accessibility a required part of every interaction contract and reconciles observable client behavior with current API, provider, concurrency, audit, and idempotency seams. It does not create routes, permissions, audit actions, domain states, retry values, or insurer policy. Runtime source remains implementation truth; a documented behavior without browser, assistive-technology, and protected-runtime evidence is not complete.

Numbered requirements, acceptance gates, exact current permissions/audit actions or gaps, flow/state/screen/API links, and UAT/test targets are owned by `../01-strategy-requirements-roadmap/iip_release_1_interaction_requirements_traceability.md`.

`Stroke return` in this segment means **focus return**: after closing a dialog/drawer, completing a transient action, reauthenticating, resolving a conflict, or returning from a child route, focus returns to the initiating control when it still exists, otherwise to the changed item or the destination task heading.

Target: WCAG 2.2 AA. The IIP interaction target is at least 44 by 44 CSS pixels for primary, consequential, destructive, icon-only, and repeated touch controls. The WCAG 2.2 Target Size (Minimum) 24 by 24 CSS-pixel rule and its exceptions are a floor, not the product target.

Normative baseline: [WCAG 2.2](https://www.w3.org/TR/WCAG22/). Pattern guidance: [WAI-ARIA Authoring Practices Guide](https://www.w3.org/WAI/ARIA/apg/), including the [modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) and the distinction between a [native/static table](https://www.w3.org/WAI/ARIA/apg/patterns/table/) and an application-style [interactive grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/). APG guidance supports implementation choices; it is not by itself proof of accessibility or WCAG conformance.

## 2. Universal interaction accessibility contract

Every `ACT-R1-*` action must satisfy all of the following.

| Concern | Required observable behavior |
|---|---|
| Keyboard | Native semantic control; logical task order; no positive `tabindex`; Enter/Space activates as appropriate; Escape cancels only before the irreversible boundary; no keyboard trap except a correctly contained modal. |
| Focus visibility | A persistent, non-clipped indicator with at least 3:1 adjacent contrast; focus is not indicated by color alone; Windows forced-colors retains a visible outline. |
| Focus entry/return | Dialog/drawer focus enters its heading or first required field, remains contained, and returns to the invoker. Route changes focus the destination heading. Validation focuses the error summary/first invalid field; conflict/recovery focuses its status heading. |
| Touch/pointer | Primary and high-impact targets are at least 44 by 44 CSS pixels; other targets meet 24 by 24 or documented spacing/inline exceptions. Target meaning never depends on hover, precision, drag, or gesture alone. |
| Name, role, state | Programmatic name matches visible purpose; role and current state (`expanded`, `pressed`, `selected`, `checked`, `disabled`, `busy`, sort, progress) are exposed. Instructions and errors are programmatically associated. |
| Announcement | Loading/saving/retrying uses a deduplicated polite status; validation/failure/permission/session loss uses an assertive alert when immediate action is required; progress exposes determinate/indeterminate semantics; success names the committed object and next state once. |
| Contrast and non-color | Normal text 4.5:1, large text 3:1, controls/focus/meaningful graphics 3:1; state is also conveyed by text/icon/shape. Placeholder, disabled, and decorative tokens never carry essential information. |
| Reduced motion | `prefers-reduced-motion: reduce` removes parallax, translation, scale, pulsing, animated progress, and nonessential transition; state changes remain immediate and perceivable through text/status. Motion never communicates the only evidence of change. |
| Zoom/reflow | At 200% zoom and 320 CSS-pixel width, content reflows without loss of action, evidence, error, or horizontal reading order; data tables provide an equivalent operable pattern. |
| Timeout/recovery | Time limits are announced before expiry where controllable; reauthentication preserves only safe committed/draft state; restored focus and announcement identify what changed and what must be reviewed again. |

## 3. Evidence layers, criteria mapping, and limitations

| Layer | Evidence this review can define/use | Current limit |
|---|---|---|
| Design evidence | Task/reading/focus order, labels, state semantics, target intent, reflow, motion alternative, error/recovery content | Low-fidelity screens are specified but not rendered/reviewed; target bounds and visual focus cannot be measured from prose |
| Implementation evidence | DOM semantics, names/roles/values, keyboard operation, actual focus, live regions, computed target size/contrast/motion/reflow | Local diagnostic sampled three screens and found failures; full current portal/component matrix not executed in this turn |
| User evidence | Supported screen-reader/browser, switch/keyboard, physical touch, zoom/reflow and disabled-practitioner task performance | No manual AT, switch-control, physical-device or disabled-user session has been completed |

| Requirement area | WCAG 2.2 baseline | IIP application |
|---|---|---|
| Keyboard | 2.1.1 Keyboard; 2.1.2 No Keyboard Trap; 2.4.3 Focus Order | Every task/action/state operable without pointer; semantic order matches task order; only a correctly modal dialog contains focus |
| Focus | 2.4.7 Focus Visible; 2.4.11 Focus Not Obscured (Minimum); 1.4.11 Non-text Contrast | Persistent visible focus, at least partially unobscured by sticky UI, with product 3:1 adjacent contrast target and deterministic entry/return |
| Semantics/status | 1.3.1 Info and Relationships; 2.4.6 Headings and Labels; 2.5.3 Label in Name; 4.1.2 Name, Role, Value; 4.1.3 Status Messages | Prefer native HTML; names match visible purpose; groups/errors/states associated; loading/success/recovery announced without forced focus |
| Touch/pointer | 2.5.1 Pointer Gestures; 2.5.2 Pointer Cancellation; 2.5.7 Dragging Movements; 2.5.8 Target Size (Minimum) | WCAG AA floor is 24×24 CSS px with defined exceptions; IIP requires 44×44 for primary/high-impact/repeated/icon controls and alternatives to precision/drag/gesture |
| Reduced motion | Product requirement R1-A11Y-009; WCAG 2.3.3 Animation from Interactions is AAA, not an AA conformance requirement | Remove nonessential translation, scale, parallax, pulsing, animated progress and transitions when reduced motion is requested; retain immediate text/semantic state |

This is a design and implementation-evidence audit, not a formal conformance statement. Legal applicability, supported technology baseline and final conformance require separately approved review.

## 5. Seven-state accessibility application

| Low-fidelity state | Keyboard/focus | Semantics/announcement | Touch/reduced motion |
|---|---|---|---|
| `LOADING` | Keep focus on initiating control/owning region; do not focus skeletons; dependent controls unavailable with reason | Named region `aria-busy`; one deduplicated polite stage/status; determinate work uses progress semantics | Skeleton/static indicator has no essential motion; cancel/recovery target remains touch-safe where available |
| `EMPTY` | Focus stays on heading/filter or valid next action; no forced jump to decorative empty state | Heading + useful explanation distinguish first use/filter/valid zero where policy permits; announce result count once | Primary valid action 44×44; no animated illustration required to explain state |
| `ERROR` | Task-blocking submit focuses error summary then first invalid field; regional/provider error focuses only on explicit recovery request or route entry; preserve prior context | `alert` only for immediate required attention; errors associated with field/control/region; possible effect and preserved work stated | Retry/correct/return targets safe; no shake/pulse; error not color/motion-only |
| `PERMISSION` | Remove newly unauthorized controls from order; if focused control disappears, move to explanation/nearest permitted heading/return | Whole-screen/region heading states changed authority without leaking restricted existence/count/content | Return/reauth/access-owner action touch-safe; no disappearing animation that masks change |
| `PARTIAL` | Successful region order remains; “missing scope/recover” link reaches affected region; unsafe controls disabled/removed legitimately | Each failed/missing region named; page status summarizes available vs unavailable without duplicate announcements | No pulsing warning; region-local recovery controls 44×44 where high impact |
| `SUCCESS` | Do not steal focus for inline success; route advance focuses destination heading; dialog returns/advances per contract | Polite status names committed object/outcome and successor once; provider acceptance/delivery/domain success remain distinct | Remove/update submit to prevent repeat; no confetti, bounce or motion-only confirmation |
| `RECOVERY` | Focus starts at recovery heading only when user enters/re-authenticates or task is blocked; returned focus identifies changed/current state | Status exposes retry/reconcile stage, owner, attempt, preserved work, cancellation boundary and terminal meanings | Retry/cancel/escalate touch-safe; reduced motion uses static progress/text; duplicate activation suppressed |

Every rendered low-fidelity frame must annotate semantic heading/landmark order, keyboard sequence, initial/return/fallback focus, live status/error owner, high-impact target bounds, modal/nonmodal behavior and reduced-motion equivalent. These annotations are design evidence only.

## 9. Verification gates

1. Static: every interaction row links purpose/authority, states, accessibility, client, API, provider, concurrency, audit, and idempotency.
2. Automated browser: keyboard path, visible focus, modal containment/return, names/labels/states, automated WCAG rules, target sizes, reduced motion, zoom/reflow, and state announcements.
3. Manual assistive technology: NVDA + Chrome and one additional supported screen reader/browser; touch device; Windows forced colors; 200%/400% zoom; no keyboard-only dead end.
4. Protected runtime: authenticated permitted and denied roles, session expiry, provider `Not configured`, conflict, ambiguous effect, reconciliation, and audit correlation.

Passing automated tests alone is not WCAG conformance. The current readiness is **source-reconciled with local diagnostic evidence; accessibility remediation, manual assistive-technology verification, and protected UAT remain blocked/pending**.
